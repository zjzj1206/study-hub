13 · Cache 组织、访问与局部性优化

依据第 13 讲 2026-10-29 课件全部 65 页及第 13 讲研讨单。第 12 章解释为什么要用缓存；本章进一步回答“一个地址去查哪一组、怎样判断命中、读写缺失怎么办，以及代码为什么会影响命中率”。下文先给定义，再按地址和访问序列推导，最后讨论存储山与矩阵分块。

Cache 在 CPU 与主存之间做什么#

  • Cache 是通常由 SRAM 构成、硬件自动管理的快速存储。CPU 请求指令或数据时先查相应缓存；命中就由这一层提供，缺失则向下一级请求，不能把每条 load 都等同于一次 DRAM 访问。
  • 多层查找：L1 miss 后可能在 L2 命中；L2 miss 后可能在 L3 命中；只有相应下层也未命中，才继续到主存。每层都有自己的命中、缺失与传输单位。
  • 时间局部性让已装入的块再被访问；空间局部性让同一个块中的相邻字节被访问。这两点分别对应“保留可重用数据”与“按整块取回数据”。
  • 读事务仍需地址、数据和控制，只是命中时无需把请求一路送到主存。写事务还要考虑上层与下层副本如何保持正确，具体由写策略决定。

先分清字节、块、行和组#

  • 内存块 block：主存地址空间中连续的 BBB 个字节；以块为单位装入缓存。
  • 缓存行 line：缓存中容纳一个内存块的位置，包含数据块及标记等元数据。“块”强调数据，“行”强调放置它的槽位。
  • 组 set：允许某个内存块放置的一组候选行。地址先决定一个组，再在组内查找；不是任意扫描整个缓存。
  • 设有 S=2sS=2^sS=2s 组，每组 EEE 行，每行数据区 B=2bB=2^bB=2b byte，地址宽度 mmm bit，则：
C=SEB,t=m−s−b.C=S E B,\qquad t=m-s-b.C=SEB,t=m−s−b.
  • CCC 是数据容量，一般不含 valid、tag、dirty 和替换状态。每组行数 E 也称相联度；课件写成 E=2eE=2^eE=2e 是常见设计参数化方式，不意味着地址另有 e 位“路号”。
  • valid 有效位：该行是否保存可用块；冷启动时通常均为 0。
  • tag 标记：区分映射到同一组的不同内存块；tag 相等但 valid=0 仍然 miss。
  • dirty 脏位：写回式缓存中，该行数据是否已被修改而尚未同步到下一层。

从地址到命中：tag、组索引、块内偏移#

图中三段地址有不同任务：中间索引选组；高位 tag 与所选组各行标记比较；低位偏移选中命中块内的字节。比较结果还必须与 valid 相与，才构成命中。

  • 对字节地址 AAA：
q=⌊A/B⌋内存块号,o=A mod B块内字节偏移,j=q mod S组索引,T=⌊q/S⌋tag.\begin{aligned} q&=\left\lfloor A/B\right\rfloor &&\text{内存块号},\\ o&=A\bmod B &&\text{块内字节偏移},\\ j&=q\bmod S &&\text{组索引},\\ T&=\left\lfloor q/S\right\rfloor &&\text{tag}. \end{aligned}qojT​=⌊A/B⌋=AmodB=qmodS=⌊q/S⌋​​内存块号,块内字节偏移,组索引,tag.​
  • 地址的位域顺序为高到低 [tag | set index | block offset]；程序表达式写成 tag=A>>(s+b)、set=(A>>b)&(S-1)、offset=A&(B-1)。
  • 读流程：确定组 j → 同时检查该组 E 行的 valid 与 tag → 某行匹配时按偏移取数据 → 若均不匹配，选择空行或牺牲行，必要时写回旧脏块，再装入新块。
  • 没有路号地址字段：哪一“路”命中由各行比较结果确定，不是从某几个地址位直接解码。
  • 跨块访问：若从偏移 o 开始读取 w byte，且 o+w>Bo+w>Bo+w>B，访问涉及两个块；应按题目约定拆分，不能只检查起始地址。后面的简单 trace 均为单字节读，避开这项额外条件。
  • 恢复旧块地址：淘汰行的 tag 为 T、所在组为 j 时，旧块首地址为 (TS+j)B(TS+j)B(TS+j)B。写回脏块必须用旧 tag 恢复地址，不能用新请求地址覆盖旧数据。

直接映射：E=1，每个组只有一个候选#

  • 结构：每组只有一行，索引选组后只比较一个 tag。缺失时若该行有效，就只能替换它，不需要在多路之间做 LRU 决策。
  • 课件例：4-bit 地址，S=4,E=1,B=2S=4,E=1,B=2S=4,E=1,B=2，故 s=2,b=1,t=1,C=8s=2,b=1,t=1,C=8s=2,b=1,t=1,C=8 byte；每次读 1 byte，初始全空。
顺序 字节地址 tag / set / offset 结果 该步之后相关组内容
1 0，即 0000 0 / 0 / 0 miss 组0装块 [0,1]
2 1，即 0001 0 / 0 / 1 hit 同一块中的另一个字节
3 7，即 0111 0 / 3 / 1 miss 组3装块 [6,7]
4 8，即 1000 1 / 0 / 0 miss 组0用 [8,9] 替换 [0,1]
5 0，即 0000 0 / 0 / 0 miss 组0重新装 [0,1]
  • 自己构造一条序列：在同一结构中访问 2,3,10,2,3，结果为 miss,hit,miss,miss,hit。地址 2 与 10 的块都映到组1，反复驱逐；地址3与2属于同一块，所以装入2后再访问3会命中。
  • 相关概念：初次访问一个块是冷缺失；最后再次访问0的缺失由映射冲突造成。空闲组的存在不能改变“该块只允许进组0”的规则。

组相联与全相联：增加每组候选位置#

  • E 路组相联：一个内存块仍只映到一个组，但允许放在该组的任一行。组内所有候选行可并行比较；通常先用无效行，组满后再替换。
  • LRU，最近最少使用：在该组内淘汰最长时间未访问的行；命中也会更新最近使用顺序。还可采用随机、伪 LRU 等策略，不能未给策略就假设唯一牺牲块。
  • 全相联：S=1S=1S=1，整个缓存就是一个组，s=0s=0s=0，所有行都是候选；冲突限制减少，但比较与替换开销增加。
  • 同容量对照课件：改为 S=2,E=2,B=2S=2,E=2,B=2S=2,E=2,B=2，仍为8 byte，t=2,s=1,b=1t=2,s=1,b=1t=2,s=1,b=1。原序列 0,1,7,8,0 变为 miss,hit,miss,miss,hit；0与8映到同一组，却可占两行共存。
  • 两路 LRU 例：上述两路结构读 0,4,0,8,4。这些块都映到组0；结果 miss,miss,hit,miss,miss。第三步命中0使4成为 LRU；第四步装8淘汰4；第五步重装4时淘汰0。
  • 保持哪些参数不变很重要：固定 C、B 增加 E，会减少组数 S，因此组索引位减少、tag 位增加。不能只把原图每组加一行却仍声称容量不变。

写命中与写缺失：两组互相独立的问题#

问题 策略 具体动作
写命中后怎样同步下层 write-through 写直达 更新缓存，同时向下一层传播写入；常配写缓冲
写命中后怎样同步下层 write-back 写回 更新缓存，置 dirty；淘汰或其他要求时再写回下层
写缺失是否把块装进来 write-allocate 写分配 先取得块放入缓存，再修改目标字节
写缺失是否把块装进来 no-write-allocate 非写分配 向下一层写入，此次不把块装进当前缓存
  • 常见组合为“写直达 + 非写分配”和“写回 + 写分配”；它们是常见搭配，不是两组策略只能这样配。
  • 下层不一定是主存：L1 写到下一层可能先到 L2，不能把每次直达都写成必须立即更新 DRAM。
  • 写回缺失的正确顺序：选目标行 → 若旧行有效且脏，按旧地址写回整块 → 装入新块并设置 tag/valid、清初始 dirty → 修改目标字节并置 dirty=1。
  • dirty 是修改状态：不因普通读取而清零；一个新装入的干净块为0，写后变1。现代系统还可因显式维护等写回，课件“只在淘汰时清零”应按本节简化模型理解。

手算一轮写回 + 写分配#

  • 假设 S=1,E=1,B=4S=1,E=1,B=4S=1,E=1,B=4，初始无效，执行 写0 → 读1 → 写4 → 读0。
  • 写0：miss，装块 [0,3]，修改偏移0，置 dirty=1。
  • 读1：hit，读同块偏移1，dirty 仍为1。
  • 写4：miss，先把旧块 [0,3] 写回，再装 [4,7]，修改偏移0，置 dirty=1。
  • 读0：miss，先把 [4,7] 写回，再装 [0,3]，读结束新行保持干净。
  • 合计1次 hit、3次 miss、3次装块、2次脏块写回；最后读到的地址0应包含最初的写入结果。

为什么用中间位索引，而不取最高位#

  • 标准划分：最低 b 位必须留给块内偏移，紧邻的 s 位让相邻内存块依次轮流进入不同组。连续扫描时容易把容量利用起来。
  • 课件 64-byte 地址空间例：缓存16 byte，直接映射，块4 byte，因此4组。标准为 TTSSBB，地址0、4、8、12分别进入组0、1、2、3。
  • 若改为高位索引 SSTTBB，这四个地址的高2位均为00，全部挤进组0，即使其余3组空闲也冲突。
  • tag 必不可少：组索引只回答“去哪个组”，多个块共享一个组；tag 才回答“当前放的是不是所需块”。不应将“选中组”当成“已经命中”。

存储山：工作集大小、步长与带宽#

  • 测量对象：纵轴是实际读吞吐量 MB/s；两个横轴分别为工作集覆盖范围和访问步长。它不是“缓存延迟”的直接三维图，也不是某个算法的渐近复杂度图。
  • 工作集大小：本轮反复访问的地址范围/数据规模；增大后可能从 L1 可容纳，跨过 L2/L3 容量，最终依赖主存。
  • 步长：相邻访问间隔。课件 long 为8 byte，stride=s 表示每隔 s 个元素，即8s byte取一个数据。
  • 课件 test 函数：四个累加器与4路展开降低单条依赖链开销；对各 elems/stride 组合先预热，再计时访问，以突出相应缓存层次。最终结果必须被使用，防止整个读取过程被优化掉。
  • 预热不保证全命中：工作集大于某层时，第二遍仍会缺失；它主要避免把所有现象都混成第一次的冷启动。
  • 课件代码边界：第34页尾循环写 i++，若目的是始终保持给定 stride，尾部应使用 i += stride；返回 int 与 long 累加器类型不一致也不适合通用基准。严格基准还应避免有符号溢出，并按真正读取的元素数计算有效字节数。

逐个解释第35页的箭头#

  • L1/L2/L3 高台和山脊：固定步长时，覆盖范围小，可在较高层重用；越过容量后出现下降，表现为时间局部性受容量约束。
  • Mem 区域：覆盖范围大到重用数据难以留在末级缓存，更多流量走主存，吞吐通常较低。
  • 空间局部性的坡面：固定覆盖范围，步长变大，一个缓存块中被有效使用的数据减少，吞吐往往下降。
  • 积极预取造成的凸起：硬件识别可预测的流式访问，提前请求后续块，掩盖部分等待；因此 stride=1 的实测表现可能好于只看需求缺失的简单模型。
  • 补充页61～65：固定 stride 的切片突出容量变化；固定128 KiB覆盖范围的步长切片突出块利用率。64-byte块可装8个8-byte元素，理想需求模型中 stride≤8 时每次访问约有 s/8 的块首次取入比例，stride≥8 时趋近1；预取、跨遍历重用、冲突和实际容量会改变实测值。
  • 第64页拟合式中的常数针对特定机器和测量条件，不是普适缓存公式；不同年代山形差别体现预取、容量和带宽共同作用。

  • 数学定义为 Cij=∑k=0n−1AikBkjC_{ij}=\sum_{k=0}^{n-1}A_{ik}B_{kj}Cij​=∑k=0n−1​Aik​Bkj​，常规算法做 n3n^3n3 次乘加量级操作。三个矩阵占 3n23n^23n2 个元素，每个输入元素在整体计算中会被重用多次。
  • 行优先 double 矩阵地址为 A0+8(in+j)A_0+8(in+j)A0​+8(in+j)；最后一维变化时步长8 byte，第一维变化时步长8n byte。
  • 第38～47页分析条件：每缓存块32 byte，即4个double；n大；缓存不能保留足够多行来跨遍历重用；忽略冲突等细节。顺行约每4个元素一个miss，跨列近似每元素一个miss，固定标量摊薄为0。

三组程序的运算意义#

/* ijk: c is assigned, sum stays in a register where possible. */
for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j) {
        double sum = 0.0;
        for (int k = 0; k < n; ++k)
            sum += a[i*n+k] * b[k*n+j];
        c[i*n+j] = sum;
    }

/* ikj: c must initially be zero; interchange outer i/k for kij. */
for (int i = 0; i < n; ++i)
    for (int k = 0; k < n; ++k) {
        double r = a[i*n+k];
        for (int j = 0; j < n; ++j)
            c[i*n+j] += r * b[k*n+j];
    }

/* jki: c must initially be zero; interchange outer j/k for kji. */
for (int j = 0; j < n; ++j)
    for (int k = 0; k < n; ++k) {
        double r = b[k*n+j];
        for (int i = 0; i < n; ++i)
            c[i*n+j] += a[i*n+k] * r;
    }
  • ijk/jik 的内层2次load、0次store；ikj/kij 虽为2次load、1次store，局部性却通常更好。这说明只数指令或访存次数不足以判断性能。
  • 写 C 的计算口径：在写分配模型下，C 的一次读改写通常是读先把块带进来，紧随的写命中，不能把同一更新无条件算两次 miss；C 循环外最终写一次的代价在大 n 的每内层摊销中趋近0。
  • 结果前提：a、b、c 不重叠；下标乘法不溢出，指针合法；累加版 C 预先置零。浮点每个元素的加法顺序若改变，或编译器形成 FMA，舍入结果也可能改变，不能只凭数学结合律保证逐位一致。
  • 第47页实测的曲线还包含具体容量、预取和处理器执行成本；上述0.5/1.25/2是特定理想模型的解释，不是任何 n、任何机器的精确倍率。

Blocking：把时间重用留在缓存里#

  • 目标：把一个 C 子块的累加与相应 A/B 子块的多次使用，安排在缓存仍能留住它们的时间窗口内。循环交换强调相邻数据，分块进一步缩短重用距离。
  • 避免符号冲突：前文 B 表示缓存行字节数；本节用 L 表示缓存行 byte、q 表示矩阵子块边长，CbytesC_{bytes}Cbytes​ 表示缓存数据容量。元素8 byte时，三个 q×qq\times qq×q 子块的容量条件为：
3q2×8≤Cbytes.3q^2\times8\leq C_{bytes}.3q2×8≤Cbytes​.
  • 这是必要的工作集估算，实际还应留余量并考虑映射冲突、其他数据、对齐和替换；不能等号装满就保证三个块都能共存。课件 3B²<C 中 C 若以元素为单位才量纲一致。
  • 程序结构：外层 ii/jj/kk 遍历子块；内层 i/j/k 完成该组三个子块的乘加；固定 ii/jj 时，对不同 kk 的贡献累加到同一个 C 子块。
  • 边缘处理：n 不一定是 q 的倍数，每层上界应取 min(start+q,n)，否则会越界；q 必须为正。下载示例使用差值检查避免边界加法溢出。完整分块 C 示例

从不分块到分块，逐步推出缺失量#

  • 第49～55页另一个模型：缓存行64 byte，装8个double；不同于前面32-byte例。以下只计 A/B 的主要读缺失，忽略 C 的较低阶/额外开销，并假设对齐、整除、有效装块和预期重用成立。
  • 不分块：固定一个 (i,j)，k 内层读取 A 的一行约 n/8 个块、B 的一列约 n 个块，合计 9n/89n/89n/8；对 n2n^2n2 个 (i,j) 重复，得到：
Nmiss,plain≈98n3.N_{miss,plain}\approx\frac98n^3.Nmiss,plain​≈89​n3.
  • 分块：一个 q×q 子块约 q2/8q^2/8q2/8 个缓存行；固定一个 C 子块，遍历 n/q 对 A/B 子块，两块合计：
nq×2×q28=nq4.\frac nq\times2\times\frac{q^2}{8}=\frac{nq}{4}.qn​×2×8q2​=4nq​.
  • 一共有 (n/q)2(n/q)^2(n/q)2 个 C 子块，于是：
Nmiss,blocked≈(nq)2nq4=n34q.N_{miss,blocked}\approx\left(\frac nq\right)^2\frac{nq}{4} =\frac{n^3}{4q}.Nmiss,blocked​≈(qn​)24nq​=4qn3​.
  • 模型下主要读缺失比约为 (9/2)q(9/2)q(9/2)q；这是缺失次数比，不是程序必有该倍数的加速。计算吞吐、C 流量、写回、边界和冲突会影响实测。
  • 课件 C≪n 的表述需要先统一容量单位：此模型意在说明缓存不足以跨完整长行/列保留全部重用数据，同时又能保留三个较小子块；不是拿“byte”和“元素个数”直接比较。

题目与实验的统一步骤#

  • 先列参数：地址宽度 m、S/E/B、初始 valid/dirty、访问大小、读写顺序、替换与写策略。
  • 每步分解地址：列块号、组号、tag、offset；只在选中组中查找有效匹配。
  • 明确顺序：读还是写，是否跨块；命中更新 LRU/dirty；缺失先处理旧脏块再装新块；随后才执行本次读写。
  • 统计口径：分别记录 hit/miss、装块、脏写回，区分访问次数、传输流量和每迭代缺失数。
  • 教材6.30～6.33：按本地 pp.453 的具体参数逐项模拟读写；不要把另一题的 S/E/B 或写策略带入。
  • 教材6.34～6.35，矩阵转置：写出 src[i][j] 与 dst[j][i] 的地址，按程序真实的读后写顺序交错模拟。源与目标即使互不重叠，也可能映到同组并互相驱逐；分块、对角元处理等应由具体缓存参数验证。
  • 可与第14章优化联读：先看访存是否成为瓶颈，再看算术依赖、编译器限制和执行单元是否成为瓶颈。

指定缓存题6.30～6.35的具体回查#

  • 6.30：本地教材 pp.453～454 指定13-bit字节地址、8组、4路、4-byte块。故数据容量128 byte，offset为低2位，index为接着的3位，tag为高8位。
  • 6.31，地址0x071A：offset=2、index=6、tag=0x38。组6有两个标记0x38的行，但一个valid=0，必须忽略；有效0x38行的数据为FA、93、EB、48，因此返回0xEB。
  • 6.32，地址0x16E8：offset=0、index=2、tag=0xB7。组2有效tag为0xBC/0xB6，均不匹配，所以miss，缓存表本身无法给出下层内存的新数据。
  • 6.33：组2两个有效块的地址范围分别为0x1788～0x178B与0x16C8～0x16CB，共8个字节地址；用 (tag*S+set)*B+offset 还原。
  • 6.34～6.35：4×4 int转置，src从0开始、dst从64开始，每元素4 byte、块16 byte，直接映射、写直达+写分配、初始为空。每次先读src[i][j]，再写dst[j][i]。两题数据容量分别32/128 byte；容量变化使组数从2变为8。

易混边界与课件补充页#

  • E 是候选行数，B 是每行数据 byte；C=SEB 不含元数据，不能把 valid/tag 存储空间遗漏到“整个芯片容量”估算中。
  • 增大块会提高相邻数据利用机会，也会减少固定容量下的行数，并可能增加无用传输；增大 E 会减少部分冲突，但不消除容量限制。
  • 一次容量能放下所有数据，不意味着直接映射下不会冲突；同一块被多个层保存，也不意味着所有层在写回策略下始终逐字节相同。
  • 第58～60页的现代处理器、芯片照片与历史容量，用于说明缓存靠近执行部件及多级组织；它们不是最新产品参数。第61～65页的预取和带宽曲线应结合各自标注的 CPU、频率和容量阅读。
