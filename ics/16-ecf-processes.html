16 · 异常控制流与进程

依据 2026-11-09 第 16 讲全部 62 页课件及本讲研讨单。主线是：系统事件使 CPU 进入内核；内核维护进程并切换上下文；程序通过 fork、exit、wait/waitpid、execve 创建、结束、回收和替换进程映像。信号与非局部跳转本讲只建立位置关系，详细机制留待后续资料。

正常控制流与异常控制流#

  • 控制流 是处理器执行的指令地址序列；顺序执行、条件分支、过程调用和返回，都是当前程序指令语义规定的正常控制转移。
  • 异常控制流（ECF） 用来响应仅靠当前用户程序的普通分支无法处理的系统事件，例如时钟到期、设备完成 I/O、缺页、非法运算。
  • 硬件异常把控制交给内核处理程序；更高层还包括进程上下文切换、信号处理、setjmp/longjmp。这些机制处在不同层次，不能把“异常”等同于某个语言的 throw。
  • call 调用普通函数通常不改变权限级；系统调用要进入内核执行受保护操作。普通跳转虽也改变 PC，但不因此成为 ECF。

异常入口、异常表与返回#

  • 事件对应异常号，处理器结合异常入口机制定位处理程序；课件的异常表是“异常号→入口地址”的模型，不是逐个执行所有处理程序直到找到合适的。
  • 进入异常处理时保存恢复所需状态，转到内核执行。处理完可能继续下一条、重试当前指令，或者不能返回原程序。
  • 在精确异常的教学模型中，需要分清：引起异常的指令、保存的恢复地址和实际是否返回。它们由异常类别和处理结果决定。
类别 与当前指令关系 常见场景 正常处理后的恢复位置
Interrupt，中断 异步，来自外部事件 时钟、磁盘或网卡完成 被中断流的下一条待执行指令
Trap，陷阱 同步，有意请求 系统调用、断点 请求指令之后
Fault，故障 同步，可能可恢复 缺页、某些保护错误 修复成功则重试故障指令；否则终止等
Abort，终止类异常 同步，严重不可恢复 严重机器检查错误 不按普通故障路径恢复
  • “同步”表示异常由该指令执行引起，不是说必须和别的进程同步；“异步”表示与当前具体指令无因果依赖。
  • 异常不都意味着程序错误：系统调用是正常请求，按需分页引起的合法缺页也可能是正常机制的一部分。
  • 课件将若干体系结构例子作概括；具体异常类别须服从目标 ISA，不能仅凭“非法指令”这个中文名称便断言它在所有机器上属于 Abort。题目明确给定类别时按其恢复语义推导。

缺页与非法地址：相同入口，不同结果#

  • 合法虚拟地址对应页面尚未驻留时，内核可准备物理页、从后备存储装入或按需分配，并更新映射，随后重试原访存指令。
  • 不满足映射或权限要求的地址不能靠“把任意页面读进来”解决；内核可能向进程送 SIGSEGV，默认动作会终止进程。
  • C 数组越界是未定义行为，不保证每次都立即触发硬件缺页。课件越界示例用于说明访问无效地址后的路径，不是所有越界的普遍检测机制。
  • 对未修复原因的可重启 fault，仅改一个结果寄存器、随后仍返回同一故障指令，会再次触发；应区分题目限定的“原地址重试”与另行修改上下文等特殊处理方式。

Linux x86-64 系统调用约定#

  • 课件表中的原始调用号属于 Linux x86-64：read=0、write=1、open=2、close=3、fork=57、execve=59、exit=60、kill=62。不要跨体系结构照搬数字。
  • C 库包装函数通常把原始错误转成 -1 并设置 errno；errno 只在返回值表明失败时检查。成功调用不保证把它清零。

DMA 与中断怎样连接起来#

  • CPU／驱动配置 I/O 操作、目标内存缓冲区和设备控制信息。
  • 设备控制器借助 DMA 在设备和内存间搬运数据，CPU 不必逐字节执行复制指令；内存权限与 DMA 映射由系统管理。
  • 传输完成后设备可发出中断，内核确认完成、更新状态，并可能唤醒等待 I/O 的进程。
  • DMA 负责数据传送，中断负责事件通知。唤醒仅意味着具备运行条件，不保证该进程立刻占用 CPU。

进程、程序与处理器#

  • 程序 是代码和静态数据的集合；进程 是程序的一次运行实例，包含执行状态与资源；处理器 是执行指令的硬件。
  • 一个程序可以有多个进程实例；一个进程经 execve 可先后运行不同程序映像，PID 不因成功替换映像而改变。
  • 两个核心抽象是逻辑控制流和私有虚拟地址空间。前者让程序像独占 CPU，后者让程序像独占自己的内存；不意味着物理机器真有等量 CPU 和独立物理内存。
  • 通过 ps -eo pid,ppid,stat,comm 或 top 观察 PID、父 PID、状态及命令；不要把多个同名命令行误认为同一个进程。

上下文切换与并发#

  • 上下文包含恢复执行所需寄存器、PC、栈指针、地址空间信息，以及内核维护的调度、打开文件等状态；不是仅保存源代码中的变量。
  • 切换过程：进入内核→保存原执行上下文→调度另一个可运行实体→切换必要地址空间状态→恢复其寄存器→返回执行。
  • 系统调用可以进入内核后仍返回同一进程；用户态／内核态切换不必然是进程切换。
  • 单个逻辑 CPU 在一个瞬间执行一个硬件线程的指令流，但可交错执行多个进程。多个逻辑 CPU 可以真正同时运行多个流。
  • 并发 是执行时间区间重叠；并行 是物理上同时执行。单核上的 A、B 可并发而不并行。
  • 用半开生命周期区间 [si,ei)[s_i,e_i)[si​,ei​) 判断两进程是否重叠，可检查 max⁡(si,sj)<min⁡(ei,ej)\max(s_i,s_j)<\min(e_i,e_j)max(si​,sj​)<min(ei​,ej​)。题目采用不同端点约定时需按题意处理。
  • 上下文切换有保存／恢复、调度、缓存与地址转换状态等成本；它仍使系统能在 I/O 等待时利用 CPU，并提供响应性与公平性。
  • 教材“内核不是独立进程”强调异常处理可在当前进程上下文执行；实际系统也有内核线程，不能据此否定它们的存在。

fork：复制运行现场，从返回处产生两条路径#

  • 原型 pid_t fork(void)；成功时父进程得到子 PID（正数），子进程得到 0；失败时调用者得到 −1，未产生子进程。
  • 父子从同一个 fork 调用的返回处继续，不是子进程从 main 开始重跑，也不是把之前已经完成的输出再执行一次。
  • 普通私有内存内容初始相同，随后修改互不影响；操作系统常用写时复制实现，逻辑上的独立不要求立即物理复制所有页面。
  • 文件描述符表被复制，但继承的描述符指向相同的内核打开文件描述，因此可共享文件偏移。不要把私有变量与共享的打开文件状态混在一起。Linux fork 手册
  • 谁先执行没有保证。课件用随机延时插桩增加运行次序变化，是帮助暴露可能交错，不是建立一种新的确定次序。
int x = 1;
pid_t pid = fork();
if (pid < 0) { perror("fork"); exit(1); }
if (pid == 0) {
    printf("child: %d\n", ++x);
    exit(0);
}
printf("parent: %d\n", --x);
waitpid(pid, NULL, 0); /* 简化示例；完整调用应检查返回值 */
  • 子进程输出 2，父进程输出 0；不是先把共享 x 加到 2 再减回 1。
  • 如果每个分支各输出两行，父行 P1→P2、子行 C1→C2 的内部顺序必须保持，跨分支可以交错。
  • 在把每次整行输出视为一个事件的题目模型下，四个带标签事件有 (42)=6\binom{4}{2}=6(24​)=6 个合法总顺序：P1 P2 C1 C2、P1 C1 P2 C2、P1 C1 C2 P2、C1 C2 P1 P2、C1 P1 C2 P2、C1 P1 P2 C2。

fork 题的系统解法：进程图与偏序#

  • 每遇到一次实际执行的成功 fork，该路径分成父子两条；先画路径再判断分支，不能仅数源码里有几个 fork 字样。
  • 每个节点是一个事件，每条有向边表示先发生关系。边来源包括同进程程序顺序、创建关系、成功等待后的约束。
  • 合法输出是事件图的拓扑序；重复文本可能来自不同节点，需先给节点加进程标签，再抹去标签判断输出字符串。
  • 没有分支过滤、退出或失败，所有存活进程都经过 n 次连续 fork 时，最终进程数 2n2^n2n，新建子进程数 2n−12^n-12n−1。

连续两次与只在父／子中嵌套#

puts("L0");
fork();
puts("L1");
fork();
puts("Bye");
  • 假设所有 fork 成功，且输出按事件立即可见：L0 1 次、L1 2 次、Bye 4 次，最终 4 个进程。
  • 若第二次 fork 只由第一次 fork 的父分支执行，则最终 3 个进程；只由子分支执行同样是 3 个，但父子关系不同。
  • 课件 p.47：L0 后原父输出 L1 再 fork，原父输出 L2，三条路径各输出 Bye。L2 不可能晚于全部三个 Bye，因为原父自己的 Bye 必须在 L2 后。
  • 课件 p.48：子分支输出 L1 后再 fork，孙进程输出 L2。原父的 Bye 可以早于 L1，但孙进程的 Bye 仍必须在 L2 后。

标准 I/O 缓冲的边界#

  • printf 执行与字符实际写到外部设备不是同一个时刻。fork 会复制用户态 stdio 缓冲；若 fork 前文本未刷新，父子正常退出时可能分别刷新同一份副本。
  • 做进程图输出题时明确采用“每次输出已刷新／无缓冲、单条输出视为不可分事件”的约定，才可直接用拓扑序计数。
  • 实验可在创建进程之前设置 setvbuf(stdout,NULL,_IONBF,0)，或在 fork 前 fflush；不能仅凭自己运行几次看到的顺序证明其他顺序不可能。

终止、僵尸与孤儿#

  • main 返回、调用 exit、收到默认动作为终止的信号，都可导致进程终止。exit 不返回；它会执行正常退出清理，包括刷新 C 标准 I/O。
  • _exit 不执行同样的用户态 stdio 刷新／退出处理，常用于 fork 后 exec 失败的子进程路径；不要无意重复刷新继承的缓冲。
  • 终止后，内核仍可能保留 PID、退出状态与统计信息，供父进程取得；这种已终止但未回收的状态叫僵尸，它不继续运行用户代码。
  • 孤儿 表示父进程先终止，子进程可仍运行；孤儿不等于僵尸。Linux 会交由适用的子收割者或 PID 命名空间中的 init 等接管，不能一概说永远是全系统 PID 1。
  • 长期运行的父进程若不回收终止子进程，僵尸记录会累积。课件“PID 1 不回收就只能重启”并非通用操作结论；关键在于接管者／父进程的回收责任。

wait 与 waitpid：等谁、返回什么、怎样读取状态#

调用／结果 含义
wait(&status) 等待并回收任意一个符合条件的子进程
waitpid(pid,&status,0)，pid>0 等待指定子进程
waitpid(-1,&status,0) 与普通 wait 的等待对象相同
成功返回正 PID 返回本次取得状态的子 PID，不是退出码
WNOHANG 且返回 0 当前没有符合条件的可报告状态，不是“已回收 PID 0”
返回 −1 失败，检查 errno；例如没有可等待子进程或调用被中断
  • 子进程若已终止且可回收，wait 可立即返回；否则通常阻塞。一次 wait 不会自动回收全部子进程，也不会直接回收任意孙进程。
  • status 是编码状态；先判断 WIFEXITED(status)，为真时才用 WEXITSTATUS(status)；信号终止用 WIFSIGNALED 和 WTERMSIG。正常退出码通常取低 8 位，不能直接把 status 当退出码。
  • 等待指定子进程建立“该子进程结束→wait 成功返回→父后续代码”的顺序，但不改变其他子进程的实际结束先后。多个已结束子进程供普通 wait 选择时，不保证按创建顺序。Linux wait 手册

父子输出的同步例子#

  • 子进程输出 HC 后 exit；父进程先输出 HP，再 wait，最后输出 CT 和 Bye。
  • 合法次序只有 HC HP CT Bye 或 HP HC CT Bye；CT 必须晚于 HC 和 HP。子进程的 exit 使它不会落到父分支之后共同的 Bye。
  • p.56 循环中子进程创建后立即退出，只有父继续创建，所以总数是 N+1N+1N+1，不是 2N2^N2N。
  • p.57 父按 PID 数组逆序 waitpid，打印回收结果可以按指定逆序；这不说明子进程也是逆序结束。

execve：换程序，不换进程身份#

  • execve(path,argv,envp) 将当前进程的代码、数据、堆栈等映像替换成新程序；成功不返回原调用点，失败返回 −1。
  • 不创建新 PID。要在保留父程序的同时运行另一个程序，通常先 fork，在子分支 exec，父分支等待或继续服务。
  • argv 是字符串指针数组，以 NULL 指针终止；argv[0] 约定写程序名。envp 是 name=value 字符串指针数组，也以 NULL 终止。
  • 字符串末尾的字符 \0 与指针数组末尾的 NULL 是两层终止标志。argc 不计末尾 NULL。
  • PID 保持；普通文件描述符通常保持，但设置 close-on-exec 的会关闭；已安装的信号处理函数在 exec 后重置为默认，不能把课件“保留 signal context”理解为全部原样保留。Linux execve 手册
  • 新程序启动栈包含参数、环境及系统辅助信息；运行时启动代码准备 main 参数。课件 p.60 是讲解视图，内核最初入口状态与直接调用 C main 的参数约定应区分。

可运行的 fork—exec—wait 骨架#

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>
extern char **environ;
int main(void) {
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); return 1; }
    if (pid == 0) {
        char *argv[] = {"/bin/echo", "ICS", NULL};
        execve(argv[0], argv, environ);
        perror("execve");
        _exit(127);
    }
    int status;
    pid_t result;
    do { result = waitpid(pid, &status, 0); }
    while (result < 0 && errno == EINTR);
    if (result < 0) { perror("waitpid"); return 1; }
    return WIFEXITED(status) ? WEXITSTATUS(status) : 1;
}
  • 正常输出 ICS，父回收子进程后返回 0；exec 成功不会执行其后的 perror。
  • 此例采用单线程教学前提。多线程 fork 后子分支允许调用的函数还有额外限制，不在本讲简化骨架中展开。

本讲解题检查表#

  • 异常题先判断同步／异步、是否可恢复、恢复地址；不要把 fault 一概写成必然退出。
  • fork 题先区分父子返回值，再沿每条路径算变量与后续 fork 次数；不要把私有变量合为一个。
  • 输出题先确认缓冲模型，再画偏序，最后数拓扑序或检验给定顺序。
  • wait 题分别记录子 PID、退出状态编码与提取后的退出码；exec 题分别记录进程身份与程序映像。
  • 第二次测验的第 16 讲填空题与本章对应；作业 8.9、8.18、8.19 的题型路线见附录 C。
