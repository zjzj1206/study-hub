08 · 机器级进阶与内存安全

来源：2026-10-08 第 8 讲 ICS08-machine-advanced-20261008.pdf，共 53 页；教材 §3.9～3.10；2025 第一次阶段测验第 23～24 题。课件主线为 union、内存布局、缓冲区溢出及防护。下文用课件页码定位，并单列此前保留的指针与调试补充。

union 的分配与位重解释（pp.3～4）#

union 各成员从相同偏移开始，共享存储；总大小至少容纳最大成员，并按最严格成员对齐要求取整。struct 则依声明顺序为每个成员分配独立空间，中间和末尾可能有填充。

union U1 { char c; int i[2]; double v; };
struct S1 { char c; int i[2]; double v; };

在课件的 int 为 4 字节、double 为 8 字节且按 8 对齐的平台：

类型 成员偏移 对齐 总大小
union U1 c、i、v 全为 0 8 8
struct S1 c 为 0；i 为 4；v 为 16 8 24

struct 中 c 后有 3 字节填充，i[2] 占 8 字节，之后再填充 4 字节才能放 double。union 没有为各成员累加空间；写入一个成员，会改变其他成员覆盖到的底层字节。“一次使用一个字段”是其通常的使用方式，不代表写入后其他字段也保存了各自独立的值。

课件用含 float f 与 unsigned u 的 union 实现 bit2float、float2bit。核心是 原位串重解释，不是数值转换：若 unsigned 的位串为 0x3f800000，在 binary32 下按 float 解释是 1.0；(float)u 则转换整数 1065353216 的数值。反过来，1.0f 的位串为 0x3f800000，而 (unsigned)1.0f 为 1。

这些例子须明确数据宽度与浮点格式。C 与 C++ 对读取非活动 union 成员的规则不同；需要检查对象位串时，可在大小相等的对象之间使用 memcpy，避免直接通过不兼容类型指针读取。不要将课堂的位重解释练习当成任意语言、任意类型均可用的保证。

端序与数据模型（pp.5～10）#

大端把最高有效字节放在最低地址，小端相反。端序决定多字节数值如何解释，不改变字符数组按地址递增排列的顺序。课件列举传统 Sun/SPARC 大端、x86 小端和可配置端序的 ARM；具体平台模式须看题目条件，网络字节序采用大端。

union {
    unsigned char c[8];
    unsigned short s[4];
    unsigned int i[2];
    unsigned long l[1];
} dw;
/* 按地址递增写入：f0 f1 f2 f3 f4 f5 f6 f7 */
读取成员 IA32 小端，long 4 字节 课件 Sun 大端，long 4 字节 Linux x86-64 小端，long 8 字节
c[0]～c[7] f0 f1 f2 f3 f4 f5 f6 f7 f0 f1 f2 f3 f4 f5 f6 f7 f0 f1 f2 f3 f4 f5 f6 f7
s[0]～s[3] f1f0、f3f2、f5f4、f7f6 f0f1、f2f3、f4f5、f6f7 f1f0、f3f2、f5f4、f7f6
i[0]、i[1] f3f2f1f0、f7f6f5f4 f0f1f2f3、f4f5f6f7 f3f2f1f0、f7f6f5f4
l[0] f3f2f1f0 f0f1f2f3 f7f6f5f4f3f2f1f0

表中均为十六进制。作答顺序是先确定 sizeof，再圈出成员覆盖的字节，最后按端序组成数值。64 位机器不保证 long 一定为 8 字节，例如 Windows x64 使用另一种数据模型。交换二进制文件时，既要约定端序，也要约定字段宽度与布局。

数组、结构体和联合的对照（p.11）#

类型 空间组织 必须注意
数组 同类型元素连续存储，步长为元素大小 满足元素对齐；C 不自动检查下标边界
结构体 按声明顺序放不同成员 成员间及末尾填充影响 sizeof 和结构体数组步长
联合 成员从同一地址重叠存放 空间共享，不能同时保存各成员独立的值

数组表达式在许多场景转换为首元素指针，但数组对象不是一个保存地址的指针变量；sizeof 数组、&数组 等场景须另行分析。

Linux x86-64 进程内存布局（pp.13～15）#

课件图是虚拟地址空间示意，不按比例绘制。从较低地址到较高地址，可看到程序代码、静态数据、传统堆区域、共享库与大块分配映射、栈；并不意味着这些区域之间没有空洞或每次运行地址相同。

区域 典型内容 生命周期与特征
Text / 代码区 main、普通函数的机器指令 一般可读、可执行，不可写
静态数据区域 全局变量、static 对象 随程序存在；未初始化或零初始化对象通常在 BSS，字符串常量通常在只读数据区
Heap / 堆 malloc、calloc、new 获取的动态对象 需按分配接口管理释放；传统堆扩展通常朝高地址
映射区域 共享库、大块动态分配 大块 malloc 可能走映射区域，不保证紧挨小块分配
Stack / 栈 返回地址、保存寄存器、需要内存的局部变量 随调用变化，x86-64 栈通常向低地址增长

课件中的 8 MB 栈限制、约 47 位用户地址范围及 0x400000 一带代码地址都是示例环境条件，不是 C 语言或所有 x86-64 系统的固定保证。地址随机化、PIE、系统配置和分配器策略都会改变实际布局。局部变量也可能被优化进寄存器。

第 14 页例子中：全局 big_array[1L<<24] 为 16 MiB，huge_array[1L<<31] 为 2 GiB，均属于静态存储；global 也是全局对象。main 内的 local 与局部指针变量通常在栈上，但 指针变量的位置不等于它所指向内存的位置。两次 256 B malloc 在示例中落入普通堆，两次 256 MiB / 4 GiB malloc 落入较高地址映射区域，函数地址位于代码区。分配尺寸是请求量，不保证分配成功，使用前须检查返回值。

递归耗尽栈空间（p.16）#

每层递归若有 int a[1<<15]，在 int 为 4 字节时，仅数组就占 128 KiB。8 MiB / 128 KiB = 64，只是忽略其他开销的粗略估算；实际还有返回地址、保存状态、对齐、已有调用栈等，不能据此保证可递归 64 层。

课件地址每层相差 0x20010，即 128 KiB 加 16 字节，最终访问栈界限之外触发段错误。return recurse(x-1)-1 在递归返回后还需减 1，不能当成普通尾调用直接认定会消除栈帧。栈空间耗尽与写越某个栈数组边界是两种问题，虽然都可能表现为崩溃。

越界不一定立即崩溃（pp.18～20）#

课件结构体含 int a[2] 和 double d，先令 d=3.14，再执行 a[i]=1073741824。在该布局下，a[0]、a[1] 合法；偏移 8 和 12 字节的位置正好覆盖 d 的两个 32 位部分。1073741824 的位串是 0x40000000，写到 d 的一半会改变浮点解释。

例中 i=2、3 得到约 3.1399998665、2.0000006104；更远越界可能损坏金丝雀、返回地址或其他状态。第 18、19 页展示的更远下标结果并不相同，正是为了说明 结果依具体系统与编译布局而变。这些访问在 C 中已经越界，属于未定义行为，不能把某个输出背成语言规定；volatile 也不提供边界保护。

错误可能先破坏数据，到函数返回或后续调用时才暴露；也可能暂时看不出影响。“输出正常”“没有段错误”都不能证明访问合法。

字符串输入为什么容易越界（pp.21～22、41）#

课件中的 gets 示例循环读取到换行或 EOF，依次写字符，最后追加 \0，但没有容量参数，因此不能保证不越界。把数组加大只能推迟问题。历史 gets 已不应在实际代码中使用。

操作 问题或正确使用条件
gets(buf) 无法传入容量；不要使用
strcpy、strcat 需自行确保目标足以容纳全部内容及结尾 NUL；strcat 还要计入已有字符串
不带字段宽度的 scanf %s 输入长度不受目标数组容量约束
fgets(buf, sizeof buf, stdin) 对于有效且容量足够的数组，至多存容量减 1 个输入字符，再加 NUL；需检查返回值、换行和截断
scanf 的 %ns n 为最大输入字符数；目标至少 n+1 字节，如 buf[4] 对应 %3s
strncpy(dst, src, n) 源长度不小于 n 时可能不写结尾 NUL；短源会补零，不能简单视为“自动安全版 strcpy”

关于 strncpy 的终止符与补零行为，可对照 GNU C 手册。

sizeof buf 只有在这里的 buf 确实是数组时才能代表整个容量；函数形参 char *buf 或退化后的数组参数，其 sizeof 是指针大小。fgets 遇到换行会保留它，puts 又追加换行；读取失败时不能盲目把未初始化缓冲区当字符串打印。

从汇编推导越界位置（pp.23～27）#

课件未保护版本为 char buf[4]，但函数入口执行 sub $0x18,%rsp，共留出 24 字节；随后 mov %rsp,%rdi 把缓冲区起点作为 gets 的参数。以减栈后的地址 S 为基准：

相对 S 的字节偏移 内容
0～3 buf[4]
4～23 本例中未使用的 20 字节
24～31 echo 的 8 字节返回地址

call echo 位于 0x4006f1，下一条指令地址为 0x4006f6，所以压入的返回地址是后者。小端内存从低地址到高地址为 f6 06 40 00 00 00 00 00。执行尾声 add $0x18,%rsp 恢复栈指针，ret 再读取返回地址并弹栈。

  • 输入 23 个普通字符时，NUL 写在偏移 23：已经远超 buf[4] 的合法范围，但课件这次没有破坏返回地址，因此还能正常返回。
  • 输入 24 个普通字符时，NUL 写在偏移 24：返回地址最低字节 f6 被改为 00，变成 0x400600，示例随后崩溃。
  • buf[4] 最多容纳 3 个普通字符加 NUL；不能把本例“23 字符未崩溃”当成安全长度。

通用做法是从汇编求缓冲区基址、栈分配量和保存区偏移，再按字节数推导；不能固定背“数组长度加 8 就到返回地址”。栈向低地址增长，但从数组起点向递增下标写入，地址向高处移动，两者不矛盾。

控制流破坏与代码注入（pp.28～34）#

正常情况下，Q 返回到调用者 P 中 call 后的指令。若越界写改掉 Q 的保存返回地址，ret 就会把被改后的值送入指令指针。课件先演示转到已有的 smash 函数，再展示返回到缓冲区内机器指令的代码注入。

分析课堂输入布局时，将其拆为“到保存返回地址之前的填充”和“按端序编码的目标地址”。课件使用十六进制转换工具把可打印十六进制表示转换为实际字节，因为地址可能包含 NUL 等不可打印字节；文本字符“40”不等于一个数值为 0x40 的字节。第 29～30 页与第 31 页的目标地址来自不同示例构建，不能混用。具体偏移与目标都须以当前反汇编为准。

代码注入要求控制流确实到达放入数据区的指令，且相应内存可执行。输入成功写入字节，不代表这些字节一定能执行。这里复习的是课内程序的控制流和防护原理。

历史案例与术语（pp.34～39）#

课件列举 1988 年 Internet worm：fingerd 的不受限输入是其利用的漏洞之一，说明单机的内存错误可能成为网络传播的入口。另一组案例是 1999 年 MSN/AIM 互通争议：课件描述 AOL 利用自身客户端的越界漏洞取得特征值来区分客户端，双方反复调整；第 38 页邮件作为历史材料展示，并注明后来被发现来自微软内部。Wii Twilight hack 也被列为案例，但课件未展开细节。

按课件定义，worm（蠕虫）能独立运行并传播自己的完整副本；virus（病毒）把代码附着到其他程序，依赖宿主运行。两者都可能传播和造成破坏，但传播方式不是同一个概念。课件关于漏洞“排名第一”的表述用于强调严重性，不应当作当前年度安全统计。

三层防护与各自限制（pp.40～47）#

机制 主要作用 限制与前提
源码层边界检查、正确限制输入长度 避免发生越界写 需正确计算容量与终止符，处理输入失败和截断
ASLR / 栈地址随机化 让目标地址更难预测；不同运行栈地址不同 不修复越界，不能保证所有代码地址都随机
NX / XD / DEP 通过内存执行权限阻止把数据区内容当代码执行 需硬件与 OS 支持；不阻止覆盖数据或复用已有代码
栈金丝雀（canary） 函数退出前发现哨兵被改变，调用失败处理 依赖编译插桩与布局；不阻止所有越界，也不是写入发生时立刻拦截
PIE（相关补充） 让主程序可被随机装载 与 ASLR 配合；不能认定所有程序默认具有此属性

第 42 页通过栈偏移随机化说明 ASLR 思想。第 43 页对比传统 x86 权限与支持不可执行数据页的环境。2025 试题据此区分：安全输入通常要改源码并重编译；栈随机化通常不需重编译普通用户程序；金丝雀通常需重编译但不必改源码；NX 依赖 CPU 支持。已有支持的机器不需为了启用 NX 再“换 CPU”。

金丝雀汇编逐步读（pp.44～47）#

课件介绍 -fstack-protector；是否默认启用、保护哪些函数取决于工具链和构建选项。第 45 页的关键流程为：

sub $0x18, %rsp
mov %fs:0x28, %rax
mov %rax, 0x8(%rsp)    # 保存参考金丝雀的副本
xor %eax, %eax        # 清除寄存器副本，不是清除栈中金丝雀
# 输入与输出操作
mov 0x8(%rsp), %rax
xor %fs:0x28, %rax    # 相同则结果为 0，ZF=1
je normal_return
call __stack_chk_fail
# normal_return: 恢复 rsp 并 ret

0x28 是十进制 40，所以 %fs:0x28 与 %fs:40 表示同一偏移；FS 段基址参与寻址，不是访问普通绝对地址 0x28。在该 Linux ABI 实现中，它用于取得线程相关区域的参考金丝雀。单凭 FS 寻址语法不能推出该区域一定只读，课件的旁注不应推广成 x86 指令规则。

本例栈中 buf 位于 0～3，4～7 是填充，金丝雀位于 8～15，16～23 是剩余空间，返回地址位于 24～31。7 个普通字符加 NUL 写到偏移 7，虽已越界但尚未碰金丝雀；8 个字符的 NUL 到达偏移 8。课件展示后者报错，但接触不等于必然改变值：若覆盖字节恰与原字节相同，比较可能仍通过。例如 glibc 的初始化实现会清除金丝雀的一个字节，参见 glibc 官方源码补丁记录。判断检测是否触发，要看保存值是否真的发生变化，不能只看输入长度。金丝雀检查也不会让前面已经发生的未定义行为变合法。

ROP：复用已有指令（pp.48～53）#

ROP（Return-Oriented Programming）将已有可执行代码中的短片段 gadget 串起来。课件的片段以 ret 结尾，普通近返回 ret 编码是 0xc3。执行 ret 时，从当前栈顶读出下一地址作为 RIP，同时 RSP 增加 8；如果片段还有 pop 等指令，也会额外消耗栈槽。

课件片段 从该入口解码的指令 效果
第 49 页函数尾部，0x4004d4 lea (%rdi,%rdx,1),%rax；ret rax ← rdi + rdx；跳过原函数前面的乘法
第 50 页指令中间，0x4004dc movq %rax,%rdi；ret rdi ← rax

第二个例子说明 x86 指令变长：同一串字节从不同起点解码可得到不同指令，gadget 不一定从原函数入口或原反汇编的指令边界开始。第 52 页按顺序组合两段后实现 rdi ← 原 rdi + 原 rdx。

执行顺序要画出来：echo 的 ret 取第一个地址，第一段末尾 ret 取第二个地址，第二段末尾 ret 继续取后继地址。课件第 53 页的 “Goes off somewhere” 表示只给两段并不保证后续能正常返回；不是执行到第二段就自动结束。覆盖的地址槽依次向高地址排列。

ROP 使用已经可执行的代码，因此不可执行栈本身无法阻止它；不执行栈上数据，也减少了对缓冲区具体地址的依赖。但它需要能改变控制流并知道可用代码地址，不自动绕过金丝雀或代码地址随机化。课件“代码位置固定”的假设适用于其示例，启用 PIE 和 ASLR 后不能照搬。

相关补充：指针、调试与对象寿命#

以下保留此前与教材对应的基础补充，不把它们算作新课件另有专页讲解的内容。

C 指针的完整概念#

指针类型决定解引用宽度和指针算术步长；强转类型不会移动对象，也不会自动创建目标对象。void* 可持有对象指针，但标准 C 不定义 void 的大小，因此 void* 算术不是可移植的标准写法；GCC 的相关扩展不能当成语言一般规则。

函数指针指向可调用函数，类型还包含参数和返回类型。数组可以存函数指针；函数不能按普通对象数组直接存储。空指针、未初始化指针、悬空指针、越界指针是不同情况；只检查非空不足以保证可访问。

调试与反汇编#

命令概念 用途
break / run / continue 断点、运行、继续
step / next 源代码级步入/步过
stepi / nexti 指令级步入/步过
info registers 观察寄存器
disassemble 反汇编函数
x/Nfu address 查看 N 个单元，f 为显示格式，u 为单元宽度
backtrace / frame 调用栈和栈帧选择

常见 x 显示宽度 b/h/w/g 是 1/2/4/8 字节；与 C 的 sizeof(long) 没有自动对应关系。打印地址时区分“地址值”和“该地址处的内容”。优化会让变量消失、合并或移到寄存器，调试器显示不出变量不一定是编译错误。

内存错误与动态栈#

数组越界、错误的指针步长、未初始化读取、对象寿命结束后访问、释放后使用、重复释放、格式化字符串错误、错误分配大小都会导致问题。内存泄漏是已分配对象不再能被正常释放，和悬空指针不同；前者未必立即崩溃，后者可能指向已经无效的对象。

变长局部数组按运行时长度分配空间，通常按对齐向上取整后减少 rsp，并可能保存稳定帧基址；退出时恢复栈指针。返回局部数组指针不会延长它的寿命。

  3. 局部指针、大块 malloc 对象、全局数组、函数各在什么区域？哪些地址可能变化？

  6. 金丝雀位于 8(%rsp) 时，7、8 个字符分别写到哪里？“碰到金丝雀”是否必然使检查失败？
  7. 源码边界检查、ASLR、NX、金丝雀各保护什么？为什么 NX 不能单独挡住 ROP？
